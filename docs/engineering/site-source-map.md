# Website sources and rendered routes

The website uses three **unversioned** docs plugins and a custom React homepage. There is no `versions.json`, `versioned_docs` or versioned sidebar tree in this build. An older component file is not operative merely because its name contains “homepage”.

| Rendered route (under `/traderX`) | Authoritative source | Build path |
|---|---|---|
| `/` | `website/src/pages/index.js` → `src/components/homepage/TraderXHomepage.jsx`, `Hero`, `Results`, `Sections`, `homepageData` | Docusaurus pages plugin, catalog JSON imports |
| `/docs/home` | `docs/home.mdx` | Classic preset's docs plugin; separate from `/` |
| `/docs/engineering/*` | `docs/engineering/*.md` | Classic docs plugin; navigation in `website/sidebars.js` |
| `/docs/learning/state-*`, `/docs/learning`, `/docs/learning-paths`, `/docs/spec-kit/state-docs` | `catalog/state-catalog.json`, `website/public-features.json`, `pipeline/generate-state-docs-from-catalog.mjs` | `pipeline/refresh-state-docs.sh` regenerates pages; do not patch generated guides alone |
| `/specs/*` | `specs/**/*.md` outside publication exclusions | `traderspec-root-specs` docs plugin; numeric prefixes removed by Docusaurus, YU prefixes retained; autogenerated sidebar reordered by `specs-sidebar-items-generator.js` |
| `/specify/memory/constitution` | `.specify/memory/constitution.md` | `traderspec-specify` docs plugin |
| `/llms.txt`, `/llms-full.txt` | Published `docs/` inputs | LLM plugin plus link normalization; it reads files separately from the docs plugin |
| Search index | Rendered site pages | Lunr plugin post-build indexing |

The old `HomepageFeatures.tsx`, `featuresTwo*`, `featuresThree*` and `feature-config.js` are not imported by the active root homepage. Editing them cannot update this homepage. OpenAPI generation scripts remain available, but no API docs plugin is configured; runtime API Explorer is documented through its own guide.

## Publication boundary

`website/public-docs-policy.js` centralizes exclusions for the docs renderer and LLM reader. Internal handoffs, migration notes, correspondence and the mixed private `docs/risk-integration` tree stay outside the site. Public behavior is maintained in the engineering pages. Specs retain requirements and component contracts, while embedded runtime-generation Markdown and evidence directories are excluded.

`remark-public-prose.js` changes prose punctuation and resolves cross-plugin/source links without editing runtime/component contracts. It preserves code, math, URLs and quoted blocks. Source and rendered checks distinguish those protected uses from prose. A build must check search and LLM outputs as well as HTML; sidebar omission alone does not prevent publication.

## Local build and inspection

```sh
TRADERX_SITE_ROOT=/traderX bash pipeline/refresh-state-docs.sh
TRADERX_SITE_ROOT=/traderX bash pipeline/refresh-state-docs.sh --check
npm --prefix website run build
npm --prefix website run check:public
npm --prefix website run serve -- --host 127.0.0.1 --port 4390
```

Use the base-prefixed local URL printed by Docusaurus. Inspect `/`, `/docs/home`, What's new, the new engineering pages, YU18 learning and its component specs. Check both desktop and mobile layout, menu links, search, diagrams and long tables. The checker writes a source/route inventory and reports broken local targets plus protected punctuation exceptions.

## Deployment selection

`.github/workflows/deploy-docusaurus-pages.yml` runs on pushes to `main` or manual dispatch. It checks out the event ref, regenerates state docs, builds with the GitHub Pages `/traderX/` base and uploads `website/build`. A local integration commit does not change that deployed ref. This refresh does not publish or claim that the hosted site serves it.

Default human-facing repository links now target `traderX-risk-integration`; `DOCS_BRANCH` can select a different source ref for builds. The learning generator has a separate `TRADERX_SOURCE_AUTHORING_BRANCH` override. Catalogued historical state branches remain labelled as historical source choices. Updating a link default does not change a workflow trigger.

AFDocs is a non-blocking check in the existing workflow. Its score does not replace a local-route, content privacy or rendered-layout audit. The local check still reports absent per-page Markdown responses and content negotiation. The hosted page check has the same Markdown limitations. AFDocs run against a nested page does not discover the site-base index reliably; inspect the root-run report separately. LLM index links use published HTML routes; `llms-full.txt` provides the combined text export.
