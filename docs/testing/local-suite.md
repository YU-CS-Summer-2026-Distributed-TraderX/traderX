# Local suite execution and RI31 profiles

Run in an owned checkout. Generation runs sequentially and changes its generated tree and maintained generated documentation; do not run this against a checkout carrying unrelated edits. Use JDK 21, a Node version supported by the Angular manifests, .NET 9, ChromeHeadless for Angular, and a private Python environment containing the pinned EOD container requirements and tick-store requirements. Java test workers use synthetic JWT fixtures; no operator secret is needed. YU18 trade-processor test workers open java.util only for the backing-capacity retention tests. Runtime JVM and authentication configuration are unchanged.

```bash
python3 -m venv /private/tmp/traderx-suite-python
/private/tmp/traderx-suite-python/bin/python -m pip install -r specs/YU18-risk-integration/generation/runtime-overrides/eod-risk-bundles/requirements-container.txt
/private/tmp/traderx-suite-python/bin/python -m pip install -r specs/YU07-historical-tick-store/generation/runtime-overrides/tick-store/requirements.txt pyyaml==6.0.3
python3 scripts/ci/local-suite.py --evidence /private/tmp/traderx-suite-evidence --python /private/tmp/traderx-suite-python/bin/python --java-home /path/to/jdk21 --containers
```

The evidence path must be new. `--part states` runs the 18 available YU source/generated wrappers and inventories live prerequisites; `--state YU10-fix-ingress` restricts a state rerun and records that partial scope. `--part components` regenerates final YU18 and runs composed Java, baseline Java, optional Testcontainers, reference/price/tick/EOD, script guards, console/Desk Node and Angular, baseline People tests, generated People build, website build and global quality gates. `--part extras` adds the two isolated Epsilon no-GC tasks, bounded memory/universe diagnostics, generated harness/CI controls, real disposable MariaDB startup-probe controls and generated/baseline legacy Angular tests and builds. The default `--part all` includes these extras. Dependencies install from local npm cache by default. Add `--fetch-dependencies` to fetch the existing lockfile versions when the cache is incomplete; the choice is recorded and lockfiles are not changed. `--part legacy --fetch-dependencies` reruns only the legacy UI; `--part website --fetch-dependencies` gives a scoped documentation-install/build rerun. The fast state walk skips lockfile resolution. Before legacy generated UI tests, the runner synchronizes its owned generated lock to the composed FDC3 manifest, retains before/after locks, then uses `npm ci`; the authoritative source locks stay intact. An install failure is recorded, never counted as a passing test. Test reports/logs are copied before subsequent attempts, with attributable nonzero counts and skipped cases. A failure returns nonzero after other independent suites finish. No blanket retry is performed.
