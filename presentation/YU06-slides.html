The problem

Everything so far was intraday

  • No official closing prices. Trades matched all day, but nothing produced the signed-off marks a firm's overnight jobs run on.
  • No overnight batch. P&L, NAV, margin, regulatory NAV — the back-office chain that runs after the close simply didn't exist.
  • No data-quality sign-off. A stale, spiked, or missing price could feed a downstream job unchecked — a silent, expensive error.
Official EOD marks and the overnight batch chain (P&L, NAV, margin, regulatory) are core back-office infrastructure for any trading platform.

Step 1 · official closes

A versioned, immutable snapshot

Session close takes each instrument's last trade price and writes a snapshot keyed by (date, version). Re-running production is a new version — never a mutation. Every consumer of a version sees identical prices (NFR-EOD01).

// close twice for the same date — live on kind
close #1  → version 1   status=PUBLISHED   instruments=20
close #2  → version 2   status=PUBLISHED   (new version; v1 untouched)
override  → version N   writes a corrected price as a NEW version, prior stays immutable
FR-EOD03/20 · correction = new version04
STEP 2 · THE FAIL-SAFE GATE

A bad price cannot be published

A price that's stale, a spike (beyond a % move vs the prior close), or missing is flagged, and publication is blocked until every flag is resolved. An operator override (with a reason) resolves it as a new version.

// live: an expected instrument with no price → MISSING
close                  v9   status=DRAFT   flagged=1   (QLTY = MISSING → publish BLOCKED)
override QLTY @100     v10  quality=OVERRIDDEN   reason="manual close"
publish                v10  status=PUBLISHED
No downstream job ever consumes an un-signed-off price. The block holds even with auto-publish on — the gate is fail-safe by construction (FR-EOD23).
FR-EOD10/11/23 · stale / spike / missing05
STEP 3 · THE DURABLE GATE EVENT

Publish drives the overnight job

Publishing emits EOD_PRICES_READY on a durable JetStream stream. position-service's consumer marks positions only against the exact snapshot version named in the event — never live ticks — writes the P&L, and emits eod.pnl.done.

// live: consumer output for the published version
eod pnl marked accounts=4 halted=0 rows=6 date=… version=4
published eod.pnl.done  {"accountsMarked":4,"accountsHalted":0,"version":4}
Durable: a consumer that was offline when the event fired still receives it on reconnect (NFR-EOD02) — verified live: a reconnecting consumer replayed the retained stream and caught up on every published version.
FR-EOD21/30/31 · version-pinned, durable06
Step 4 · consumer fail-safe

Held back, never guessed

An account with any holding that has no published close is halted — held back from marking rather than marked with a guessed or stale price (FR-EOD32). Redelivery of the gate event is idempotent (NFR-EOD05).

// live: an account holds a security absent from the published universe
HALT account=10031  reason=missing_or_flagged_closing_price  version=5
eod pnl marked accounts=3 halted=1   (others marked; 10031 held back)
