The problem

The platform had no memory of the market

  • Prices were ephemeral. Ticks flowed on the bus and vanished — nothing stored history to query later.
  • No real data for the analytics that need it. VWAP volume profiles, better TCA benchmarks, VaR return series — all need stored, historical ticks.
  • Synthetic-only. No path to fold in real third-party market data (NYSE TAQ) alongside the platform's own.
Stored, queryable market data is the raw material for execution algos (YU08), execution-quality analytics (YU05 TCA), and risk/scenario work — it's infrastructure the rest of the roadmap builds on.

THE COMPONENT · CAPTURE + NORMALIZE + QUERY

Two sources, one schema

Live capture

passive NATS subscriber · zero hot-path impact

Subscribes to the existing pricing.* and trades broadcasts and batches rows to columnar Parquet, partitioned by source/date/symbol. No ack, so a capture outage can't back-pressure any publisher (NFR-TS01/02).

TAQ normalize

real NYSE TAQ → the same schema

Ingests NYSE TAQ Consolidated Quotes and Trades files into the identical Parquet schema — streamed straight from the zip (unzip -p), never extracting the multi-GB CSV to disk (NFR-TS03).

Proven libraries — DuckDB for columnar query, unzip for archive streaming — not a hand-rolled format or engine (NFR-TS04).
capture (live) + normalize (TAQ) → Parquet03
THE PAYOFF · ONE QUERY, BOTH SOURCES

Live and historical, uniformly

Every row carries a source field (live vs taq), so a single DuckDB-over-Parquet query reads across both — filtered by symbol/date — with no per-source special-casing (FR-TS06/07).

// self-check: capture rows + real TAQ sample → one store → one query
source=live  event_type=price_tick  rows=1   (TraderX pricing.*)
source=live  event_type=trade       rows=2
source=taq   event_type=quote       rows=4   (NYSE Consolidated Quotes)
source=taq   event_type=trade       rows=2   (NYSE Consolidated Trades)
VWAP(IBM) across the store = 136.6000   — live + TAQ trades, one query ✔

Live proof · off the running cluster

Capturing the platform's own ticks

Pointed at the live cluster's NATS, the capturer records real TraderX ticks into the unified store — no change to the order path, just a passive subscriber.

// capture.py against the running cluster, 25s window
subscribed to pricing.* and /accounts/*/trades
flushed 45 rows … flushed 45 rows … flushed 15 rows
captured rows=105  symbols=20  files=51   source=live
   NVDA  price_tick  price=892.182 …   JPM  price_tick  price=195.485 …
Runs as an independent, restart-safe process writing to Parquet (local or GCS via an S3-compatible HMAC key) — capacity and availability fully decoupled from the trading path.
