The gap YU09 left

A hardened OMS no counterparty could connect to

  • FIX is the protocol of the sell-side. Brokers, exchanges, and buy-side desks integrate over FIX — almost nobody writes to a custom REST API.
  • REST was the only order-entry surface. Correct, risk-screened, journaled — but not the door a real trading partner arrives at.
  • REST has a per-order ceiling. Every order pays an HTTP parse + JSON envelope + a blocked request/response round-trip; two internal experiments to widen it (async MVC, microbatching) both regressed throughput. The ceiling is the transport, not the engine.
The difference between "a working demo trading system" and "a system a counterparty can actually onboard to." YU10 closes it without touching the matching core.

THE MECHANISM · IN-PROCESS ACCEPTOR

A FIX order is bit-identical to a REST order past the front door

A QuickFIX/J acceptor runs inside the order-matcher (no separate gateway, no internal hop). The session thread translates each message onto the same multi-producer input ring REST uses — same risk screen, same journal, same DB projection, same recovery.

FIX session (:18130) → translate → input ring → risk screen → match → journal
— identical from the ring onward to a REST order —
match → output ring → ExecutionReport handler → session (async)
QuickFIX/J owns the hard part — the session layer: logon, heartbeats, sequence numbers, resend windows, persistent stores. The reference engine, not a hand-rolled subset.
ADR-034 · engine + topology03
SECURITY · FAIL-CLOSED IDENTITY

A session logs on with proof, or it doesn't log on

  • JWT at logon. Password(554) carries a JWT, resolved once through the same entitlement gate the REST path uses — reused for every message on the session.
  • Mapped CompID. SenderCompID must be in a committed allowlist bound to one account. No fallback, no anonymous account.
  • Fail-closed regardless of the REST flag. A brand-new surface has no installed base to keep working, so it starts closed — unmapped CompID or bad/absent token is rejected at logon.
  • Cluster-internal. The port isn't internet-exposed; TLS/mTLS is the recorded gate before any public exposure.
Verified live: a session presenting a garbage token never reaches the application — rejected at logon. A valid token + mapped CompID trades.

CORRECTNESS · ASYNC LIFECYCLE + DURABLE CORRELATION

Orders stream in, reports stream out, nothing is lost or ambiguous

MESSAGES

CORRELATION

Durable ClOrdID ledger

Binds each client order id to the internal order ref, on the PVC — joined on a field every event already carries. No change to the wire format or matching core. Rehydrates on restart; a re-used ClOrdID is rejected as a duplicate.
