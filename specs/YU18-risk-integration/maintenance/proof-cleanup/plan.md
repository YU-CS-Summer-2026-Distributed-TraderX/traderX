# Proof cleanup implementation

Status: implemented; local acceptance complete; review pending.

1. Keep lifecycle ownership in the direct runner `scripts/yu15/run-proofs.sh`. The script delegates to a Python supervisor before rig mutation and re-enters as its controlled child. Keep proof body and image builder ownership with RI-18.
2. Capture the affected StatefulSet and Deployments into a private atomic journal. Keep target identity and all restoration fields durable before subprocess launch. Give the runner an inherited exclusive lease and an owned process group.
3. Treat preparation reset intent separately from cleanup. Explicit reset authorization records irreversible data effects; check mounted PVC backing and preserve the prior image-change fence. Stop on failed preparation commands rather than interpreting partially applied preparation as success.
4. Stop owned processes before cleanup. Preflight rig identity/UIDs. If member configuration changed, quiet client Deployments. Before any image rollback, consume separately reviewed retained compatibility evidence; missing/unknown or invalid evidence keeps members untouched, clients quiet and the journal unfinished while independent settings can restore. Only an admitted boundary may stop all members, restore their templates while stopped and restore the original member count with PVCs retained. Repeat admission before patch/start and on retry. Verify actual pods before restoring clients. Persist each cleanup step before applying it, and verify exact recorded fields after application.
5. Restore other borrowed configuration, including absent probes/env, original non-default replicas and temporary restart annotations. Retain unfinished state and errors on failure or interruption. Explicit recovery repeats the same recorded intent, rechecks pods, and never substitutes a fresh epoch.
6. Exercise the original runner and fixed runner with independently initialized fake workloads, real child processes/signals, partial command failures and negative controls. Render only the component documents through existing state generation; no service/generation input change is needed for direct repository tools.

Dependencies: RI-18 proves selected content identity for a future real STP run; it supplies no retained compatibility authorization. A separate independently executed/reviewed snapshot-plus-tail/state-comparison artifact is required before a different member image can be restored. No production compatibility producer is implemented here, so unknown real boundaries remain blocked. Shared component/backlog index additions are proposals delivered to the coordinator; this lane does not modify those indexes.
