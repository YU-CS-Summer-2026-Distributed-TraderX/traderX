# Proof cleanup requirements

Status: implemented and source-tested with controlled offline processes. Live acceptance pending.

- **FR-PC01 — Capture before mutation.** Persist exact workload UID, replicas including field absence, container images, env including valueFrom and absent keys, startup/readiness/liveness probes and restart annotation. Capture all workloads borrowed by runner/STP preparation, including optional absence. Commit intent atomically with file and directory fsync before launching the runner.
- **FR-PC02 — Preserve target identity.** Record context, namespace, API server, cluster fingerprint and namespace UID. Preflight every workload UID before any recovery write. Refuse target drift, missing/replaced workloads or container membership changes.
- **FR-PC03 — Cleanup lifecycle.** Supervise the actual runner, stop its process group before cleanup, and run cleanup for success, failed preparation, failed proof, TERM and INT. Track only owned forward PIDs. Preserve the original runner exit status and distinguish cleanup failure.
- **FR-PC07 — Proof outcomes.** Preparation attempts, actual script executions and terminal outcomes are separate counts. Every failed prerequisite is a failure, including the final selected proof. Require a terminal outcome for every selected proof; a complete cleanup cannot turn an unexecuted proof into success.
- **FR-PC08 — Retained compatibility admission.** Before restoring a different member image, require an independently reviewed snapshot-plus-tail/state-comparison artifact bound to immutable writer/restore references, journal UUID, target/member identity and complete retained PVC boundary. Record potential reset/STP writers before mutation. Refuse missing/legacy/unknown/mutable writer identities and missing, mismatched, incompatible, readiness-only or empty evidence. A producer/provenance label, replica count, readiness or reset/image authorization flag is insufficient. Keep clients quiet and the journal unfinished on refusal; restore independently safe non-member configuration where possible. Repeat admission before stop, patch and restart and on recovery. No destructive fallback. This lane consumes reviewed evidence and supplies no real compatibility producer.
- **FR-PC04 — Restore exact configuration.** Restore recorded fields rather than manifest forms or assumed replicas/env defaults. Handle partial preparation and partial cleanup. Verify restored fields; member restoration requires all original pods on recorded images and ready before clients return, including on a retry after the template was already restored.
- **FR-PC05 — Durable unfinished state.** An exclusive journal lease prevents overlapping invocations and survives supervisor-only loss in its runner descendants. SIGKILL/host loss leaves unfinished intent. The next runner refuses it; explicit recovery is idempotent and leaves completed journals unchanged. Cleanup errors and catchable interruption during cleanup retain the next step and unresolved explanation.
- **FR-PC06 — Bound destruction.** Require ALLOW_PROOF_RESET=1 before preparation resets, retain the existing ALLOW_IMAGE_CHANGE refusal, and record irreversible intent before reset commands. Refuse data mounts without PVC backing and PVC retention policies that delete claims on scale-down. Cleanup may stop PVC-backed members together to prevent mixed images, but never deletes storage, clears SQL or remints an epoch. If restoration is unsafe or cannot be verified, retain unfinished intent and fail.
- **NFR-PC01 — Bounded and private.** Give the whole cleanup one 660-second command budget. Use standard Python/Bash tooling and private mode-0600 journals; persist no kubeconfig credentials. Never infer that traps handle SIGKILL or that a mock proves cluster correctness.

Acceptance scenarios use the real runner and helper, with a controlled proof child and fake rig commands. Success restores an independently defined complete original fixture. Failed preparation stops before the proof. Failed proofs retain failure after successful cleanup. Signals and cleanup failure produce distinct terminal results. Negative controls change target identity, workload identity, backing storage and member readiness; every refusal must precede unsafe mutation. The unchanged reviewed baseline is exercised to show interrupted preparation actually strands state.

Exclusions: proof-created trades and other application data, disaster recovery, automatic rollback across incompatible retained formats, image provenance, real compatibility-proof production, runtime implementation, deployment and branch propagation. The member readiness check follows compatibility admission and confirms running container identity/readiness. The admission consumer validates the bindings and complete checks in a trusted reviewed artifact; it cannot authenticate a reviewer or prove that arbitrary supplied JSON reflects a real execution. Independent artifact review and separate authorized live proof remain required.
