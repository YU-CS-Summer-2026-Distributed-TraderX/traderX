# Generated build-input derivation

Status: implemented and tested locally; coordinator review/integration pending. Owner: Codex RI20-GENERATION-DERIVATION. This is build reliability tooling; no service or runtime protocol is added.

The cluster, service and STP builders now refuse a generated context that does not match independent full generation of the selected state from current source bytes. Rebuilding a stale context no longer pairs old generated bytes with a current composition hash. The guard covers templates, ancestor patches/overrides, additions, removals, pruning and dirty owner content; it does not rely on mtimes, clean Git status, directory existence or a caller's receipt.

`generation-derivation.py` snapshots current source privately and runs the actual recursive `pipeline/generate-state.sh`. It does not regenerate the checkout or canonical generated tree. All selected service contexts are admitted before the first compilation/image operation. Ordinary builders compile private admitted copies, so cached outputs or a later change to the caller's generated context cannot enter that compilation. STP preparation and each role build independently compare against current derived fix or known pre-transform content.

```bash
TRADERX_SKIP_LOCKFILE_REFRESH=1 bash pipeline/generate-state.sh YU18-risk-integration
python3 scripts/yu15/generation-derivation.py check --state YU18-risk-integration \
  --component order-matcher --component trade-processor \
  --evidence /private/path/derivation-evidence
bash scripts/yu15/build-cluster-image.sh
bash scripts/yu15/build-service-images.sh trade-processor position-service price-publisher
bash scripts/yu15/build-stp-boundary-images.sh
```

The build commands perform real compilation/image work when the operator invokes them with real tools. This task exercised those entrypoints only with synthetic external commands. `check` performs local generation and comparison without invoking Gradle/Docker. Node/npm tooling must be installed; private generation requests offline npm resolution and fails closed when required cached metadata is unavailable. No dependencies are installed by the guard.

`BUILD_STATE` selects a catalog state explicitly, including an intentional ancestor; the default retains the existing highest-YU-pack selection. A candidate must match that state's complete derivation. Legacy `YU18-eod-risk-bundles` maps to the canonical YU18 ID. Cluster tag overrides and the service tag policy are retained; this guard does not change deployment/pinning decisions.

`OM_DIR` requires `OM_ROLE=fix` or `OM_ROLE=pre`. The copy must exactly match independently generated order-matcher or that context with the accepted zero-fuzz STP patch. Arbitrary transforms and forged `prepared.json` or private-context environment values do not bypass admission. The role is not production/deployment or retained-compatibility authorization.

Private source capture is conservative. It includes tracked and current untracked/dirty source bytes, directory membership and executable modes; it excludes local Git administration, generated outputs, build/cache directories and runtime scratch. Symlinks/unsupported source objects refuse. The actual generator must succeed without excluded outputs; they cannot silently act as inputs. Git HEAD objects are fetched locally into independent private administration for generator revision metadata, preserving dirty snapshot bytes. No canonical index or object alternate is shared.

There is no trusted persistent derivation cache: each admission derives independently. Unchanged cached image/source cases remain admissible, but this adds generation latency and temporary disk use. Spec/output receipts record ancestry, source inventory hash and complete context hashes; a receipt is evidence of the check, never a future skip token. Current source changes during capture/admission refuse.

Source owners: root `scripts/yu15/{generation-derivation.py,build-cluster-image.sh,build-service-images.sh,build-stp-boundary-images.sh,stp-image-provenance.py}`. Runtime/generation inputs remain state-parent-owned. RI18's label schema and image payload/role checks remain separate. LR05 deployment/content obligations and retained compatibility remain open.
