# Image admission plan

Owner: Codex RI20. Status: implemented offline in an isolated dependency stack, pending review.

1. Reproduce the baseline omission and stale GKE default through safe command doubles. Record source revisions and traces.
2. Consume accepted RI18 source/payload hash primitives and RI17 cleanup boundaries without extending either into production compatibility.
3. Define an independent expected-slot plan and sealed offline inspected/reviewed artifacts. Verify explicit source/generation ownership and structured rendered container coverage.
4. Make the GKE entrypoint inspect by default, bind explicit target/state/manifest owner, and apply only the admitted snapshots when separately authorized. Keep the selected-lineage schema ordering.
5. Check node refs before proof preparation and before rebuild destruction, including baseline reuse. Never repair stores as a side effect.
6. Exercise actual entrypoints with positive and negative offline controls, accepted dependency regressions, real local kustomize parsing, YU18 generation/document mapping and required gates. Return commits/evidence to the coordinator; leave shared indexes as proposals.

Operative runtime inputs remain `specs/<state>/generation/runtime-overrides/<component>` composed by the existing pipeline. Deployment manifests remain state-owned cluster/gke inputs. This component adds tooling and documentation; it does not change engine decisions, wire/snapshot/data schemas, service payloads or actual manifests' image pins.

Remaining external work: per-component real inspected production artifacts/reviews, a deliberate immutable pinning decision, live target/node/registry verification, separately authorized deployment and retained-format qualification. No class-window task performs those operations.
