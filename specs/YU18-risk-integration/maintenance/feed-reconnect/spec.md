# Feed reconnect specification

Status: implemented and locally verified; coordinator review needed. Author: Codex RI23. Interface: existing pricing.NATS/SBE plus local recovery logs. External pricing/model contracts, deployments and retained rigs are excluded.

- FR-FR01: Initial connection is attempted once with existing native initial message timeout; failure closes owned resources, reports FAILED_START and main exits1. NATS startup failure remains terminal. Reconnect applies after established transport only, not indefinite cold-start waiting.
- FR-FR02: Own closed/disconnected ingress, CLOSED/NOT_CONNECTED/MAX_POSITION_EXCEEDED offer, session CLOSED/ERROR and native Aeron exceptions enter per-incident recovery. Retire/close old client before creating another. Monotonic elapsed time bounds admitted attempts/backoffs; attempt message timeout is capped by remaining budget. Late successful connect is closed/refused. Exhaustion reports EXHAUSTED and terminates; close failure is terminal FAILED, not a reason to create another concurrent client.
- FR-FR03: Each connection attempt has a process-local generation and own symbol-ID/pending-registration maps. Callbacks write only their captured session's maps and require active session/native session ID. Requests count monotonically across attempts, never reset on reconnect. New connections re-register; no old IDs copied. Foreign/stale/short ACKs cannot certify a current registration. This generation is not an authoritative cluster epoch or quorum witness.
- FR-FR04: One NATS subscriber and embedded driver remain owned for the adapter run; each Aeron client is owned for one session and closes on retirement/finally. Native AsyncConnect resources close on failure, successful DONE transfers client ownership. Interrupted loop/connect/backoff stops visibly, prevents subscriber startup after stopped connect, closes resources with interrupt cleared for cleanup and restores it afterwards. Shutdown hook signals owner interruption and is removed when run exits.
- FR-FR05: Preserve price parser/envelope/scales, inherited50ms flush/default keepalive1s/short poll sleep, owner-only codec/offer ordering and cluster-stamped eventTime0. Keep latest pending value through local unaccepted/unknown offer failure; remove only the value observed on a positive offer, retaining newer arrival during backpressure. Already-offered quotes are not replayed. NATS buffering is nondurable/latest-only; duplicate possible after an unknown begun offer, with no exactly-once or committed delivery claim.
- FR-FR06: FEED_RECOVERY JSON contains state/time, local generation, attempts/episode attempts, connect failures/successes/recoveries, failure type, native session ID, NATS status, configured retry bounds and quote/symbol counts. CONNECTED is adapter transport scope, not quorum, price freshness, book convergence or financial validation. Missing quote activity does not trigger recovery. Legacy sequenced count means observed positive price publication returns, not committed ACKs.
- NFR-FR01: No gateway/queue/correlation/core/risk/producer/model/financial/wire/snapshot/venue change, global-health watchdog or missing-trades liveness. Existing native/NATS dependency versions remain.
- NFR-FR02: Qualify mocks, virtual time, actual native process and live acceptance separately. No synthetic measured value is a deployment/HA/throughput/financial guarantee.

## Local settings and calibration

| Variable | Local default | Unit/meaning |
| --- | --- | --- |
| FEED_RECONNECT_BUDGET_MS |10000| Per detected-loss incident, including old client close, attempts and waits |
| FEED_RECONNECT_BACKOFF_MS |100| First wait after a failed reconnect; first attempt is immediate |
| FEED_RECONNECT_MAX_BACKOFF_MS |1000| Exponential backoff ceiling; waits clip to remaining budget |
| FEED_RECONNECT_ATTEMPT_MS |1000| Reconnect native message timeout cap, clipped to remaining budget |

All durations must be positive and convert safely to nanoseconds; maximum backoff must be at least initial. FEED_FLUSH_MS must remain positive. Existing initial native5s message timeout is unchanged; it is not the reconnect attempt cap.
